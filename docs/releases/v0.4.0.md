# v0.4.0

This release makes packaging more reproducible, gives operators more control over compression and
cache preparation, and adds runtime diagnostics. Releases continue to target native Linux amd64
and arm64 with the CLI, full and minimal launchers, and native installer helpers.

## Breaking change: migrate Format v1 packages

Format v2 is now the only supported package format. v0.4.0 tools and launchers reject legacy
Format v1 JSON indexes, and `pack` and `pgo-pack` reject `--format-version 1`. A standalone fat
executable carries the launcher it was built with. Rebuild each legacy bundle before deploying
it with v0.4.0 tooling.

Use the original architecture-specific Linux ELF payloads, or rebuild them from source. Update
any packaging scripts that explicitly request Format v1. For example, repackage baseline and
v3 amd64 payloads with an installed v0.4.0 CLI and its matching launcher:

```bash
microfat pack --arch amd64 --format-version 2 \
  -v v1=dist/app_v1 -v v3=dist/app_v3 -o dist/app-format-v2
microfat verify dist/app-format-v2
```

Verify and exercise the replacement on a supported host before replacing the deployed bundle.
Existing Format v2 bundles are already in the supported format. See the
[format specification](../architecture.md#5-legacy-format-v1-removal) and
[#427](https://github.com/EpicBlackWolfZ/microfat/issues/427).

## Reproducible packaging and compression

- Direct `pack`, manifest-based `pack` and `pgo-pack` accept `SOURCE_DATE_EPOCH` for new package
  metadata, including zero and dates before 1970. Identical input bytes and options with the same
  toolchain and codec can produce byte-identical packages. See
  [reproducible creation epochs](../cli-reference.md#reproducible-creation-epoch).
- Repeat `--variant-compression <level>=<codec>[:<compression-level>]` to choose an explicit codec
  or level for an individual variant. It works for direct and manifest-based packaging, including
  `pgo-pack`. See [compression precedence](../cli-reference.md#compression-precedence-and-profile-resolution-contract).
- Opt in to `--dict-profitable` to embed a shared Zstandard dictionary only when it makes the complete
  package strictly smaller. The packer compares both encodings, which adds packaging work. The
  `latency`, `balanced` and `size` presets retain their established selection policy. See
  [the dictionary evaluation](../zstd-frame-and-dict-profitability.md) and
  [the complete-cost profile comparison](../codec-policy-results.md).
- Multi-variant Pack can hash and compress in parallel when the effective CPU and memory budgets
  admit multiple workers. Serial fallback and canonical write order preserve deterministic assembly.
  Pack also reduces redundant input reads and heap allocations. See
  [parallel Pack](https://github.com/EpicBlackWolfZ/microfat/pull/415) and
  [input reads and allocations](https://github.com/EpicBlackWolfZ/microfat/pull/413).
- Codecs use single-shot Zstandard for small payloads and bounded block concurrency for LZ4 when
  resources allow. See [codec changes and measurements](https://github.com/EpicBlackWolfZ/microfat/pull/416).

## Cache operations and runtime diagnostics

- Cold cache materialization hands the verified descriptor directly to the launcher for execution.
  Launchers also reduce hot-path trailer, cache and memfd work. See
  [descriptor-bound dispatch](../architecture.md#7-cache-first-auto-dispatch--descriptor-bound-execution) and
  [launcher changes](https://github.com/EpicBlackWolfZ/microfat/pull/417).
- `microfat prewarm --plan` previews cache work without changing the cache or executing a payload.
  `--max-payload-bytes` checks unique selected logical bytes before lookup or materialization, even
  for a fully warm selection. See [prewarm and its costs](../lifecycle-modes.md#when-prewarming-repays-its-cost).
- `runtimeinfo.Read()` exposes launcher hints, environment settings and observed Go runtime values
  with explicit source and availability fields. The documentation includes runnable Prometheus and
  OpenTelemetry recipes. See [runtime metadata](../runtimeinfo.md).
- `microfat doctor --gc-profile` and `--live-heap-estimate` preview tuning for the supplied settings.
  The JSON `tuning_preview` records input sources and `applied: false`. See
  [tuning preview](../cli-reference.md#tuning-preview-and-input-precedence).

## Performance evidence

The disabled-telemetry and requirements-exact experiments retained the existing production
implementations after their adoption gates remained unmet. The historical service-p99 review
accepted the bounded inconclusive result and shipped no runtime fix for that signal. See
[telemetry results](../disabled-telemetry-snapshot-results.md),
[selector results](../requirements-exact-selection-hosted-results.md) and
[service-p99 results](../hosted-p99-investigation-results.md).

Before tagging, record the native paired Pack results for
[#423](https://github.com/EpicBlackWolfZ/microfat/issues/423) and the reviewed matched-cost
deduplication decision for [#410](https://github.com/EpicBlackWolfZ/microfat/issues/410).
The Pack protocol covers byte identity, timing and measured cgroup peaks on native Linux amd64 and
arm64. The deduplication evaluation uses production Zstandard levels and includes the cost of
reconstruction in the decision.

## Release tooling and acceptance

- The release pipeline uses Go 1.27.4 and GoReleaser 2.20.2. Release artifact validation checks the
  compiler version in the CLI, both launchers and installer helpers. See
  [compiler enforcement](https://github.com/EpicBlackWolfZ/microfat/pull/449) and
  [security delivery](https://github.com/EpicBlackWolfZ/microfat/issues/441).
- SBOM schema validation fixes spurious regex timeouts under CPU load. See
  [the validation fix](https://github.com/EpicBlackWolfZ/microfat/pull/429).
- Scheduled advisory scans cover the source modules and authenticated stable release binaries.
  Dependabot checks every day and includes indirect Go modules. See
  [dependency maintenance](../dependency-updates.md) and
  [advisory scanning](https://github.com/EpicBlackWolfZ/microfat/pull/451).

The tagged candidate requires native installer and runtime qualification, signed inventory
verification, and complete hosted benchmark evidence before immutable publication. After publication,
audit the signed Linux archives and SBOMs, verify that the binary advisory scan clears
`GO-2026-6859`, and record public native installer and Homebrew acceptance with the exact tap commit.
See the [release order](../roadmap.md#reusable-release-order-and-exit) and
[release artifact guide](../release-artifacts.md).
