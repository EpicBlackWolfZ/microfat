# v0.2.5 release notes

This release completes the [v0.2.5 milestone](https://github.com/EpicBlackWolfZ/microfat/milestone/13):
Go-based repository tooling, Task workflows, modern release SBOMs, staged CI and documented
release verification. It also fixes benchmark helper execution and nested CPU quota reporting.

## Developer and CI workflows

- Use `task` instead of `make`. The root and demo Taskfiles replace both Makefiles, including
  build, test, coverage, lint, profiling, benchmark and snapshot commands. Task 3.53.1 is pinned
  in CI; see [contributor setup](https://github.com/EpicBlackWolfZ/microfat/blob/v0.2.5/CONTRIBUTING.md).
- Repository Python helpers have been replaced with Go commands. Coverage merging, benchmark
  matrices, evidence verification, release finalization, kernel provenance and release auditing
  run without Python or BLINT. Existing validation and failure behavior remain enforced.
- Formatting respects ignored files consistently. Local plans, generated fixtures and evidence
  under `.work/` no longer enter formatting checks accidentally.
- Pull request validation runs fast checks first, then race tests and exact coverage, then
  integration, fuzz, developer workflow, snapshot, benchmark, kernel and CodeQL checks.
  The required `CI Complete` result rejects missing, failed, cancelled or unexpectedly skipped jobs.
- CodeFactor uses the supported `revive.toml`, with the numeric complexity ceiling aligned to
  golangci-lint. Shared helpers and standard assertions remove actionable duplication and test
  boilerplate. [Specific complexity exceptions](https://github.com/EpicBlackWolfZ/microfat/blob/v0.2.5/QUALITY_EXCEPTIONS.md)
  preserve readable validation, descriptor ownership and independent test oracles.

## Runtime and benchmark correctness

- Benchmark subprocess helpers launched from the released, memfd-backed CLI now execute the
  same selected image. Running a benchmark no longer depends on reopening a transient memfd name.
- Nested cgroup CPU limits in benchmark environment reports are compared as quota/period ratios.
  The selected quota retains its matching period; malformed or missing finite periods are
  unavailable instead of being combined with an ancestor's period. Comparisons avoid integer
  overflow and floating-point rounding.
- Installing into a newly created user-writable destination does not unnecessarily require sudo.
- Executable test fixtures handle transient Linux `ETXTBSY` with bounded retries before execution.
  Failed commands and retry exhaustion still fail the test; executed payloads are never retried.

## Release trust and SBOMs

Each Linux architecture archive now has **CycloneDX 1.7** and **SPDX 3.0.1** SBOMs. A pinned
standalone cdxgen converter is combined with a Go inventory of the actual archive, full/minimal
launchers and embedded variants. Schema checks and independent product inventory validation
require module identities, versions, relationships, hashes and build metadata to survive conversion.
Historical v0.2.4 assets keep their original SPDX 2.3 and CycloneDX 1.5 documents.

The [threat model](https://github.com/EpicBlackWolfZ/microfat/blob/v0.2.5/SECURITY.md#8-threat-model-and-enforcement-map)
and [release verification guidance](https://github.com/EpicBlackWolfZ/microfat/blob/v0.2.5/docs/release-verification.md)
map guarantees to enforced boundaries and explain the trust bootstrap before first execution.
Authenticate the checksum manifest before checking an archive or executing its contents:

```bash
cosign verify-blob \
  --certificate-identity 'https://github.com/EpicBlackWolfZ/microfat/.github/workflows/release.yml@refs/tags/v0.2.5' \
  --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' \
  --bundle checksums.txt.sig checksums.txt
```

Verify the chosen archive and SBOM checksum entries against that authenticated manifest. Release
automation stages signed assets as a draft and publishes only after product validation and exact-source
hosted evidence qualification. Native amd64/arm64 compatibility and sustained benchmark evidence
remain mandatory. Hosted results are comparative, with `release_eligible=false`; this release does
not claim dedicated-hardware certification or a measured performance improvement.

Go 1.27.1 remains required. Format v2 remains the default, and deprecated Format v1 reading is
still supported. Archives contain the fat CLI and full/minimal launcher stubs for Linux amd64 and arm64.
