# v0.2.4 release notes

This correctness patch addresses the [v0.2.4 milestone](https://github.com/EpicBlackWolfZ/microfat/milestone/12)
across binary input handling, Linux launch behavior, manifest builds, cache verification, installation,
and release evidence qualification.

## Binary and build correctness

- `microfat verify --json` now exits unsuccessfully when any payload fails verification, while retaining structured results.
- Binary, stub and manifest inputs reject empty and special files without blocking on FIFOs; ordinary regular-file symlinks remain supported.
- Packing rejects relocatable objects, shared libraries without an executable entry, invalid load segments and unusable entry points.
  Native executables, dynamic PIE and static PIE remain supported. The explicit ELF validation bypass remains available.
- Relative manifests anchor PGO profile paths to the manifest directory, including paths with spaces and nested package builds.
- An omitted dictionary-size flag preserves the manifest setting; an explicitly supplied flag takes precedence even when it equals the CLI default.

## Linux execution and tuning

- Launchers read the kernel-held executable image through `/proc/self/exe`. Unlink or atomic replacement after exec no longer changes the payload selected by that running launcher.
- Full-launcher transformation commands reject a deployment path that no longer identifies the running image. In-place operations also recheck before rename; deployments and transformations still need external serialization.
- Memfd creation explicitly requests `MFD_EXEC`. Only `EINVAL` triggers a legacy-flag retry for older kernels; policy and seccomp denials remain enforced. Mandatory seals, payload verification and forced-memfd failure semantics are preserved.
- AMD64 v2 and higher require LAHF/SAHF, matching Go's startup requirements. Missing baseline features select a compatible lower variant or reject an incompatible forced level before extraction.
- The `batch_etl` profile automatically disables ordinary percentage-based GC only with a finite effective memory ceiling. Launcher and `runtimeinit` paths preserve explicit GOGC choices and report skipped automatic tuning. GOMEMLIMIT remains a soft runtime budget, not an OOM guarantee.

## Operations and packaging

- CLI, full-launcher and library cache verification use read-only directory discovery and validation. Verification does not create directories, repair permissions, extract payloads or remove corrupt entries.
- The installer tracks its elevation decision explicitly, so a new system-owned destination can receive the intended sudo mkdir attempt despite restricted shell IFS.
- Missing or corrupt packed trailers now mention possible post-pack ELF rewriting. Strip/debug-split native inputs before packing; preserve final packed bytes during installation and downstream packaging.
- Asset-location and re-exec guidance distinguishes the kernel-held image, original deployment hint and extracted cache payload. The original-path hint is informational and cannot authorize self-update or identify an authenticated publisher.
- The editable v0.2.3 release notes and source documentation now identify its actual release-workflow signature chain.

See the [runtime guide](https://github.com/EpicBlackWolfZ/microfat/blob/v0.2.4/docs/runtime-tuning.md), [lifecycle guide](https://github.com/EpicBlackWolfZ/microfat/blob/v0.2.4/docs/lifecycle-modes.md),
[packaging guidance](https://github.com/EpicBlackWolfZ/microfat/blob/v0.2.4/docs/release-artifacts.md#preserve-packed-bytes-during-packaging-and-installation),
and [troubleshooting](https://github.com/EpicBlackWolfZ/microfat/blob/v0.2.4/docs/troubleshooting.md).

## Evidence and compatibility

Hosted publication qualification now checks observed warmup/load durations, total trial duration,
effective sampling intervals and checksummed telemetry coverage. Short or partial observations cannot
qualify merely because the configuration declares a complete schedule. Missing observations fail the
publication gate with an explicit reason. See the [documented timing tolerances](https://github.com/EpicBlackWolfZ/microfat/blob/v0.2.4/docs/benchmarks/README.md#hosted-release-evidence).

Regression coverage includes real manifest/PGO builds, bounded FIFO probes, full/minimal launcher
deployment replacement/unlink tests, GNU strip order, CPU feature masking, memfd policy semantics,
non-mutating cache snapshots and offline evidence qualification. Release automation additionally
requires native amd64/arm64 compatibility and sustained hosted evidence before publishing the draft.
Hosted evidence remains comparative with `release_eligible=false`; no dedicated-hardware certification
or performance improvement is claimed.

Go 1.27.1 remains required. Format v2 is the default; Format v1 reading remains supported and deprecated.
The archive layout remains the fat CLI plus full and minimal launcher stubs for Linux amd64 and arm64.

## Verify release downloads

After downloading `checksums.txt` and `checksums.txt.sig` from this release, authenticate the manifest:

```bash
cosign verify-blob \
  --certificate-identity 'https://github.com/EpicBlackWolfZ/microfat/.github/workflows/release.yml@refs/tags/v0.2.4' \
  --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' \
  --bundle checksums.txt.sig checksums.txt
```

Verify the chosen archive and SBOM checksum entries before execution. Archives have SPDX 2.3 and
CycloneDX 1.5 SBOMs; verified hosted benchmark evidence is attached separately. The normal release
workflow stages signed assets as a draft and publishes only after the complete evidence gates pass.
