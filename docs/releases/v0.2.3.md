# v0.2.3 release notes

This patch delivers the safety and measurement foundation from the completed
[v0.2.3 milestone](https://github.com/EpicBlackWolfZ/microfat/milestone/7).

## Safety and correctness

- Bound legacy Format v1 JSON parsing and reject malformed values and excessive nesting.
- Reject privilege-bearing full and minimal launcher execution before application side effects.
- Select ARM64 variants by required CPU features across the v8/v9 branches.
- Reject FIFO/special cache files without blocking and enforce cache file ownership and modes.
- Snapshot packaging inputs through bounded descriptor reads and bound dictionary sampling.
- Account for retained memfd storage and extraction estimates when computing soft memory budgets.
- Use shared default/minimal race and coverage checks, pinned actions and job-scoped permissions.

Cache execution assumes trusted same-UID writers. Descriptor pinning protects against pathname
replacement, while sealed memfd provides immutable extracted storage. Explicit
`MICROFAT_EXEC_MODE=memfd` fails closed when unavailable; the unset auto mode may fall back to cache.
GOMEMLIMIT remains a soft Go-runtime budget and cannot guarantee freedom from container OOM kills.
See [the security boundary](https://github.com/EpicBlackWolfZ/microfat/blob/v0.2.3/SECURITY.md#7-launcher-and-cache-deployment-boundary).

## Reproducible measurement

The benchmark CLI now supports paired native/fat mixed, CPU and memory server experiments with
pinned external Fortio load, isolated processes, cgroup controls, scoped telemetry, deterministic
reports and checksummed raw evidence. Native amd64/arm64 compatibility matrices cover full/minimal
profiles, supported format/codec/dictionary combinations, memfd and cache execution.

Pre-release validation includes [kernel enforcement](https://github.com/EpicBlackWolfZ/microfat/actions/runs/34457699727),
[release and compatibility rehearsals](https://github.com/EpicBlackWolfZ/microfat/actions/runs/34457951314),
and [independent archive verification](https://github.com/EpicBlackWolfZ/microfat/actions/runs/34471868616).
These rehearsal measurements identify source `ead88c9112e90bf7cae520b1e36cb3253b7cf783`
and baseline v0.2.2; they are not measurements of a later commit.
The tag workflow generates and attaches evidence for the actual release revision before publication.

Hosted evidence is comparative and keeps `release_eligible=false`. Current calibration classes lack
sufficient independent training/holdout samples, so startup enforcement remains report-only; the
5% size gate remains active. Partial exec traces are explicitly qualified. No speedup or
dedicated-hardware certification is claimed; [#182](https://github.com/EpicBlackWolfZ/microfat/issues/182)
tracks that separate work. See [benchmark usage and limitations](https://github.com/EpicBlackWolfZ/microfat/blob/v0.2.3/docs/benchmarks/README.md).

## Release artifacts

Linux amd64 and arm64 downloads include specialized CLI variants, full/minimal stubs and universal
fat CLI archives, with SHA-256 checksums, a Cosign checksum-signature bundle and SPDX/CycloneDX SBOMs.
The release is staged as a draft until the build and hosted evidence workflows succeed and all
assets are attached, then published as an immutable release. SBOM generation failures stop the build.
Verify publisher identity and downloaded bytes externally before executing any artifact.

Go builds continue to require Go 1.27.1. Format v1 reading remains supported alongside Format v2.
