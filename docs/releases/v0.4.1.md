# v0.4.1

> **Pre-publication notes:** This document summarizes the changes prepared for `v0.4.1` ahead of tagging. Signed-candidate qualification, release digests, and immutable publication records will be added after `v0.4.1` is tagged and published.

This patch release hardens release asset verification and installer bootstrap path handling, tightens Format v2 binary index validation, fixes launcher unsafe-cache error telemetry, aligns release audit archive preflight checks, and updates documentation and benchmark guest kernel locks. Linux `amd64` and `arm64` retain the same Format v2 binary layout, three-product archive layout, and native installer helpers as `v0.4.0`.

## Security and reliability fixes

- **Eliminate `Lstat`-to-`Open` TOCTOU windows ([#471](https://github.com/EpicBlackWolfZ/microfat/issues/471)):** Added `inputfile.OpenRegularNoFollow` (`O_RDONLY|O_NONBLOCK|O_NOFOLLOW` on Unix plus post-open `f.Stat()` and `os.SameFile` verification against initial `os.Lstat`, allowing zero-byte regular files) and switched `installrelease.VerifyDigest` and `releasecheck.ValidateChecksums` to verify the single opened descriptor without following symlinks or blocking on FIFOs.
- **Reject non-root trailing slashes in installer bootstrap staging paths ([#470](https://github.com/EpicBlackWolfZ/microfat/issues/470)):** Hardened `safe_staging_parent` in `scripts/install.sh` so trailing slashes on symlinked or non-root `--staging-dir` values are rejected cleanly rather than dereferenced during symlink checks.
- **Tighten Format v2 `BinaryIndex` validation ([#468](https://github.com/EpicBlackWolfZ/microfat/issues/468)):** Rejected unexpected trailing bytes in `UnmarshalBinaryIndex` (`ErrInvalidIndexSize`), rejected `uint64` offsets and sizes exceeding `math.MaxInt64` while keeping negative pre-1970 `CreatedUnix` epochs signed, and enforced clean `DictionaryOffset`, `DictionaryID`, and `DictionarySHA256` values when `DictionarySize == 0` across `MarshalBinaryIndex`, `UnmarshalBinaryIndex`, and `ValidateBounds`.
- **Accurate unsafe-cache telemetry details & dead-code removal ([#469](https://github.com/EpicBlackWolfZ/microfat/issues/469)):** Updated `cmd/microfat-stub` cache error reporting in `executeViaCache` and `executeExistingCache` to emit `"refusal to execute symlink"` for symlink entries and `"refusal to execute unsafe cache entry"` for non-regular or unsafe entries (instead of misreporting `"symlink detected in cache"`), and removed the superseded `createTempFileAt` helper.
- **Align release audit tar preflight with archive extraction ([#473](https://github.com/EpicBlackWolfZ/microfat/issues/473)):** Updated `releaseaudit.preflight` to accept clean `tar.TypeDir` (zero-size) and legacy `tar.TypeRegA` entries alongside `tar.TypeReg`, matching `releasecheck.ExtractArchiveSafely` while still rejecting unsafe paths, duplicates, and special file types.

## Documentation, qualification, and maintenance

- **CLI reference telemetry table & navigation placement ([#472](https://github.com/EpicBlackWolfZ/microfat/issues/472)):** Documented `MICROFAT_ORIGINAL_EXE`, `MICROFAT_CGROUP_HIGH_BYTES`, `MICROFAT_CGROUP_EFFECTIVE_LIMIT_BYTES`, and `MICROFAT_CGROUP_GOGC_SKIPPED_REASON` in the [exported telemetry variables table](../cli-reference.md#exported-downstream-runtime-telemetry-variables), and moved bottom navigation links to the end of `docs/cli-reference.md`.
- **Supported versions policy:** Updated [`SECURITY.md`](../../SECURITY.md) to reflect the `v0.4.x` active Format v2 release stream and mark `< v0.4.0` end of life.
- **Guest kernel lock refresh:** Updated `benchmarks/kernel.lock.json` to verified Ubuntu Jammy kernel `5.15.0-204.214` image and module `.deb` packages.
- **Bootstrap and updater qualification:** Updated the `v0.4.1` bootstrap helper pin and added `v0.4.0` to native installer/downgrade qualification matrices (`scripts/qualify-installer.sh`, `tests/e2e/update_test.go`, and [the verification contract](../release-verification.md)).

## Compatibility and release order

There is no new binary format, archive layout, or supported operating-system target in `v0.4.1`. Format v2 remains the only supported format. Source CI and unsigned local snapshots establish code correctness and packaging invariants prior to tagging; signed-candidate qualification, hosted comparison evidence, and public acceptance records apply strictly to the tagged release candidate. See the [release order](../roadmap.md#reusable-release-order-and-exit) and [release artifact guide](../release-artifacts.md).
