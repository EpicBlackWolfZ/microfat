# Security Standards Compliance Matrix & Roadmap

This document tracks `microfat`'s technical alignment across international, US, German BSI, EU/Austrian, cryptographic, and supply-chain security standards, alongside committed `v0.5.0` conformance targets and deferred hardening tracks.

## 1. Product Scope & Evidentiary Boundary

- **Product profile**: Apache-2.0 Linux (`amd64`/`arm64`) CLI packager (`cmd/microfat`), self-dispatching ELF launcher stubs (`v0.4.1`: Go `cmd/microfat-stub`; `v0.5.0` target: native Rust `minimal` default + `full` stub), verified installer/updater (`cmd/microfat-install` + [`scripts/install.sh`](../scripts/install.sh)), and Go runtime libraries (`runtimeinit`, `runtimeinfo`).
- **Network & data surface**: Zero network listeners in the launcher stub; only an opt-in loopback diagnostic `pprof` endpoint in `cmd/microfat`; outbound HTTPS exists solely in explicit install, update, advisory-scan, and qualification tooling. `microfat` processes no PII, payment data, health records, or multi-tenant SaaS workloads.
- **Evidentiary discipline**: Every status in this matrix reflects **verifiable repository, cryptographic, and CI evidence** — strictly distinct from third-party accredited certification, conformance seal issuance, or legal compliance determinations. Non-commercial open-source distribution is distinct from commercial EU/regulated product placement, though commercial downstream adopters embedding `microfat` binaries inherit supply-chain obligations that this repository actively supports.

### Status Definitions

| Status | Meaning |
| :--- | :--- |
| **Conformant** | Technical requirements within `microfat`'s scope are satisfied and enforced by repeatable automated tests, proofs, or CI/release gates. |
| **Technical Readiness Conformant** | All technical controls and documentation obligations applicable to non-commercial open-source infrastructure are satisfied and verified; statutory filings requiring commercial entity status (e.g., CE marking, EU Declaration of Conformity) remain N/A. |
| **Partially Conformant** | Core controls exist in production or CI, with concrete, tracked gaps open in Milestone `v0.5.0`. |
| **Aligned** | Downstream organizational/adopter standard is actively supported by `microfat` artifacts (SBOMs, signatures, immutable releases, advisory scans, formalized assurances). |
| **Not Conformant** | Required mechanism is not yet emitted or verified in production releases. |
| **Not Assessed** | External scoring or badge evaluation has not yet been integrated into repository workflows. |
| **N/A — Out of Scope** | Standard governs domains outside a stateless Linux CLI binary packager / self-dispatching launcher (e.g., enterprise ISMS auditing, HTTP APIs, sector-specific OT/medical/automotive systems). |

## 6. Maintenance & Review Triggers

Update this matrix in the same PR whenever any of the following changes land:
1. Changes to cryptographic primitives, hash implementations, or CAVP/randomness usage (`internal/format`, `internal/pack`, `rust/crates/*`).
2. Changes to outbound HTTPS clients or download scripts ([`internal/installrelease/client.go`](../internal/installrelease/client.go), [`internal/homebrew/download.go`](../internal/homebrew/download.go), [`internal/kernelsetup/kernel.go`](../internal/kernelsetup/kernel.go), `scripts/*.sh`).
3. Changes to release signing, SLSA provenance, SBOM schemas, license audits, or advisory scan pipelines ([`.github/workflows/release.yml`](../.github/workflows/release.yml), [`.github/workflows/release-audit.yml`](../.github/workflows/release-audit.yml), [`.github/workflows/advisory-scan.yml`](../.github/workflows/advisory-scan.yml)).
4. Promotion or retirement of launcher stubs (`minimal` default promotion, Go stub retirement) or updates to [`SECURITY.md`](../SECURITY.md) support windows and disclosure policies.
